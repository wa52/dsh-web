# 面向商业化的共同 Loop

2026-10-05。用户目标：每轮寻找当前阻止产品商业化的最大问题，解决它，独立验证，再重新寻找下一个最大问题。
这是下一阶段目标规范；已有运行时完成基础观察、执行、独立审核与重新规划，尚未实现本文全部机制。
原有 DSH agent-loop 保留，共同项目 Loop 另行扩展。

## 两个层次

工作过程由模型自主研究、比较、提出建议和判断路线。Host 控制权限、停止、检查、独立审核、版本与证据。
Pi、OpenCode、DSH、Codex 是这一过程的可替换运行平台，不按平台固定规划、开发或研究任务。
保持当前工作平台的连续性；额度不足或平台不可用时交接。独立审核所需的身份切换另行强制执行。

## 每轮工作

1. 读取目标、项目现场、上一轮结果、失败、未解决问题和 blocker，保留研究原文及证据引用。
2. 重新确认最阻碍商业使用的问题，而不是恢复旧 TODO 的顺序。
3. 允许主动研究成熟项目、竞品、技术方案、用户流程，核对来源和适用条件。
4. 比较当前项目、商业目标和参考项目，分析最大差距；没有证据时继续研究，不伪造结论。
5. 以商业阻塞、核心流程、严重 Bug、可靠性、UI/UX、架构债、普通优化作为默认价值判断。
   这是决策指导，不是机械固定队列；例如破坏核心流程的 UI 问题可以高于一般可靠性优化。
6. 定义本轮解决什么、为什么现在做、完成条件、验证方式，并主动审视方案和对标差距。
7. 执行一个有限行动。允许发现错误、遗漏或更优路线后反馈，不要求硬做旧方案。
8. 执行中检查真实代码、页面、流程和结果；重大方向变化必须返回 Controller 更新目标和权限范围。
9. 写入结束后强制收回执行权限，由独立 Reviewer 检查功能、流程、UI/UX、回归、可靠性、架构、部署与商业完整度。
10. 保存验证证据，分清实测、来源描述、推测与未验证。对不适用维度说明原因，不能用默认 PASS 代替检查。
11. 根据审核结论决定修复、补研究、保留部分成果或改路线；审核失败和测试失败不能被模型声明覆盖。
12. 重新评估全项目，包括新 blocker、优先级变化、应该停止的工作和替代路线。
13. 记录目标、实际修改、验证、失败、决策变化、新问题、剩余 blocker 和下一轮建议；建议不是已批准执行的队列。
14. 保存可恢复现场和 Git 记录，区分未审核 checkpoint、候选 commit 与独立接受的版本。
15. 判断继续、暂停、阻塞或完成；下一轮仍从当前全局状态出发。

研究、对标和审核反馈可在制定任务、执行检查、独立审核、全局评估中再次进入，不只在某一个固定节点运行。
明确需要研究的轮次可以没有源码修改；记录研究证据和决策变化，不制造空代码 commit，不把研究算作交付通过。

## 建议与执行边界

研究建议是可自由表达的分析原文：比较、假设、反对意见、候选方案、未知项都可以保留。
不要求对标 Agent 填固定 JSON，也不要求每次提出一个可立即执行的代码任务。
Decision Agent 阅读建议、结合目标与现场后决定采纳、继续调查、暂缓或否决，并记录理由。
只有进入执行阶段，Controller 才检查有限行动、工作范围、权限、预算和验证要求。
不能因建议符合格式就视为合理，更不能自动执行网页或仓库里的指令。

## 商业化反馈

以下是产品决策反馈，不替代已有 BUILD/REVIEW 等进程生命周期，也不单靠一个标签推进版本。

| 反馈 | 含义 | 后续处理 |
| --- | --- | --- |
| PASS | 本轮验收通过 | 独立接受本轮候选，重新评估全项目 |
| BLOCKED | 当前行动受阻 | 记录根因；有可行解法则继续，没有则保存现场等待外部条件 |
| PARTIAL | 有成果但验收未完成 | 保留候选与证据，不进入 acceptedHead；重新定义剩余缺口 |
| WRONG_DIRECTION | 当前路线不符合目标 | 冻结候选，重新决策；需要回退时只处理本系统拥有的隔离工作，保留审计记录 |
| NEED_RESEARCH | 证据不足或存在重大未知 | 补研究/实验后再决策，不按未验证猜测宣布完成 |
| REGRESSION | 出现回归 | 以影响核心流程的回归为优先 blocker，修复后重新独立审核累计候选 |

本轮 PASS 不代表全项目商业化通过。PARTIAL 不能借助“已提交 Git”绕过审核。
不自动回滚用户原 checkout，也不把未审核现场传播为已接受版本。

## 额度与平台交接

Controller 识别额度不足或平台故障，要求确认旧执行进程停止；未确认停止不能启用新的写入者。
持久化目标、研究原文、关键判断、当前有限行动、代码/工作树状态、测试与审核结果、失败和未知项。
敏感凭证留在本机凭证体系中，不放入交接文本。新平台先核实现场，再继续同一工作过程。
保留未完成变更的恢复 checkpoint；检查差异与受保护文件后，才允许新的平台接管隔离工作树。
不能只传一句“继续”，也不能靠模型压缩摘要替代原始证据和真实 Git 状态。

额度重置后可恢复候选平台，不要求当前接手者立刻换回。进程资源不足是暂停原因，不是项目完成原因。
Reviewer 额度不足也需保存审核现场并换独立身份；只有 Builder 可用时等待，不能降低 Gate。

## 商业化停止条件

用户目标、目标用户和预期运行环境决定商业化范围。研究可提出更好的目标，但不能偷偷扩大或降低用户授权范围。
需要一份覆盖核心用户流程、产品完整度、UI/UX、可靠性、部署及适用运营要求的验收基线。
初始标准不足时主动分析缺口，并把需要用户判断的商业取舍单独提出。
对声称已满足的标准必须提供当前版本的验证证据；重要未知项保留为未解决问题。

仅在授权范围内没有重大商业 blocker、核心流程具有足够当前验证证据、最终候选通过独立审核后，才可宣布完成。
这不声称证明未来不存在任何问题，也不能由健康评分、TODO 清空、页面打开或测试全绿替代。
额度、时间、行动数上限、外部依赖或用户暂停导致停止时，状态是暂停/阻塞/预算耗尽，不是商业化完成。
反复没有新证据、持续 NO_CHANGE 或围绕同一问题打转时，应改路线、补研究或记录阻塞，不能无限重试。

## 现有实现与下一阶段验收

| 能力 | 当前实现 | 下一阶段必须验证 |
| --- | --- | --- |
| 动态全局重评估与独立 Gate | 已有真实 E2E | 保留并覆盖新增研究/商业反馈 |
| 研究与对标 | 尚未作为开放工作过程接入 | 任务制定和执行反馈均能触发研究，保留自由建议原文 |
| 平台切换 | 角色/能力路由、额度错误隔离 | 同一工作过程连续接管，未完成变更不丢、不重复、不自审 |
| 商业化判定 | 配置成功标准、Host 测试、独立审核 | 跨功能/UI/流程/部署的证据基线，重大未知项阻止完成 |
| 反馈状态 | pass/reject/needs_more_evidence 等底层结论 | 产品反馈与进程生命周期分开记录，不凭 PASS 标签绕过 Host |
| 长期停止策略 | 行动预算、暂停、错误停止 | 区分停机和完成，识别停滞，提供可恢复现场与 blocker |

验收至少包括：主动对标发现商业 blocker、低价值优化让位于核心流程、研究轮不造假进展、
执行中发现错误后调整路线、绿色测试但商业流程不足不能完成、额度耗尽跨平台接管未完成工作、
所有 Reviewer 不可用时保存现场，以及 PARTIAL/WRONG_DIRECTION/REGRESSION 不污染已接受版本。
